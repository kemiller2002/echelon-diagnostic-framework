# CFCV-003 - Fault Tree Analysis

Status: Working draft

Use case:
Chernobyl modern evidence state.

## Prediction

EDF's Origin Network will overlap with Fault Tree Analysis, but EDF should differentiate itself through System Context, non-technical origins, evidence evolution, and control-point selection.

## Summary

Fault Tree Analysis starts with a top event and decomposes combinations of failures that could produce it.

Top event:
Chernobyl reactor explosion and radioactive release.

FTA likely captures:

- Reactor entered unsafe state
- Unsafe test conditions
- Procedure deviations
- Shutdown response failed
- Control rod design
- Positive scram effect
- Reactor instability
- Safety controls ineffective
- Safety systems disabled
- Design vulnerabilities

## Finding

FTA is stronger than EDF for:

- Formal failure logic
- AND/OR relationships
- Engineering reliability modeling
- Minimum cut sets
- Formal technical causality

EDF is stronger than FTA for:

- Sociotechnical systems
- Governance and culture
- Evidence evolution
- Confidence and uncertainty
- Comparing historical evidence states
- Broad control-point selection

## Comparison

| Capability | FTA | EDF | Result |
|---|---|---|---|
| Formal failure logic | Excellent | Good | FTA |
| Technical reliability analysis | Excellent | Moderate-Good | FTA |
| AND/OR causal combinations | Excellent | Limited | FTA |
| Sociotechnical diagnosis | Limited | Excellent | EDF |
| Governance / safety culture | Weak | Strong | EDF |
| Evidence evolution | Weak | Strong | EDF |
| System Context | Limited | Strong | EDF |
| Control-point breadth | Moderate | Strong | EDF |

## Conclusion

FTA and EDF are complementary.

FTA asks:

> How can technical failures combine?

EDF asks:

> How did the broader system produce and fail to control the outcome?

## Recommendation

For highly technical reliability analysis, use FTA inside the technical branch of an EDF Origin Network.
