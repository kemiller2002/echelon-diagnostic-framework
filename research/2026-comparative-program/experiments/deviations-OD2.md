# OD2 deviation and change log (after preregistration freeze)

| # | When (relative to held-out results) | Change | Effect on confirmatory analysis |
|---|---|---|---|
| D-1 | After freeze, held-out runs in progress, **no held-out result scored or viewed** | Added the `verdicts` command to `harness/Analyze.fsx`. It implements the preregistered §4 decision rule, H10 test–retest, and class, domain and M5 breakdowns. `frozen-prompts-OD2.sha256` covers the earlier `Analyze.fsx`, whose hash no longer matches. Prompts, plan, cases, truth and scoring code are unchanged. | None to the analyses themselves. They were preregistered; the command only computes them. |
| D-2 | Held-out runs in progress; no result viewed | `harness/Claude.fsx` now waits for the child process asynchronously (`WaitForExitAsync`), to avoid thread-pool starvation with large queues. The running held-out phase was started with the earlier, behaviourally identical version and was not restarted. | None. Session arguments, isolation and recording are unchanged. |
| D-3 | **After held-out results were scored and viewed** | The vote arm (A_VOTE5) first computed acquisition on the *union* of the five member runs' reads. Because each member may read 2 items, the union exceeds the 2-item budget by construction, so acquisition was zeroed mechanically (6 of 24 "breaches"). The preregistration specified only "majority vote; cost summed", not how acquisition is aggregated. A_VOTE5 now uses the **mean of the members' acquisition**, since every member obeyed the budget. The union version is still reported, as **A_VOTE5U**. | Both are reported. A_VOTE5 vs B: score changes from −1.48 to the value in `verdicts.md`; accuracy is unaffected (+2.19). This is a post-hoc analysis choice and is labelled as such everywhere it is used. |
