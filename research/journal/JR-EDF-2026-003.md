# Research Journal

## Objective

Convert the unresolved EDF-specific incremental-value question into a controlled executable benchmark without manufacturing evidence.

## Baseline

The experiment branch began at `b27f5fff3f258e7b6d14bc9d800370bc778c54e7` and was initially byte-identical to `main`.

## Design decisions

- HY-EDF-008 is the only directly promotable hypothesis.
- Natural analysis is secondary; matched-neutral is the primary comparator.
- Six new synthetic cases were created to provide hidden ground truth while reducing prior-knowledge leakage.
- The neutral prompt was made deliberately strong.
- All conditions use the same output contract.
- The evaluator rubric uses generic constructs and is checked for EDF-specific vocabulary leakage.
- Primary unit is case x analyzer-executor, yielding 18 EDF-vs-neutral pairs.
- The primary margin is +5 points and was frozen before any run.
- E1/E2 disagreement >=20 points requires E3 adjudication.
- Failed and invalid attempts must remain in the ledger.

## Engineering record

A zero-dependency Node 22 harness was added with commands for validation, analyzer execution, evaluator execution, and aggregate analysis.

The harness validates frozen SHA-256 hashes, case/condition counts, rubric weights, neutral-control prompt strength, treatment-language leakage, executor readiness, and the randomization seed.

Analyzer/evaluator subprocesses run from empty temporary working directories. Confirmatory runs are blocked until exact provider, model, version, adapter path, and adapter SHA-256 values are committed.

## Negative result preserved

No independent model-provider execution was available through the current tool environment. This was treated as a hard experimental limitation rather than replaced by personas or repeated use of one model family.

Therefore analyzer runs remain 0 and aggregate analysis correctly returns `not-evaluable`.

## Verification

Local benchmark tests passed before commit.

GitHub Actions Repository quality run `35615737451` passed on commit `851f6840682bf8a9f23e76a163669a76d5319c0c`, confirming the committed experiment files, frozen hashes, repository validator, and benchmark validator are coherent on a clean runner.

## Interpretation

This work increases confidence in the validity of the future experiment, not in EDF performance.

The decisive next event is not more narrative analysis. It is binding independent executors and running the preregistered benchmark without changing the frozen design.
