# Research Journal

## Objective

Deep-review the Echelon Diagnostic Framework repository, challenge its proof and assumptions, test repository integrity, and upgrade the framework/research system where the evidence justified change.

## Baseline

Repository: `kemiller2002/echelon-diagnostic-framework`

Baseline commit: `f5c8e5cde6e372a616c866ed80a555cee866738e`

The baseline contained two partially contradictory layers:

1. later adversarial research correctly narrowed EDF's evidence claims;
2. older current-looking ledgers, reproducibility pages, and public website copy still displayed stronger confidence.

It also contained two website implementations even though GitHub Pages deployed only `static-site/`.

## Investigation

Reviewed the framework specification, constitution, model, principles, complexity levels, calibration protocol, Framework Engineering documents, evidence ledger, reproducibility findings, topology findings, validation protocol, adversarial experimental synthesis, contradiction registry, failure-mode taxonomy, frontier report, website architecture, deploy workflow, and website source.

The review distinguished framework coherence from framework performance.

## Findings

### JR-F-001 — Structural conformity had been mislabeled as reproducibility

Historical R1 outputs were generated inside a shared research system. Raw executions, exact prompts, model IDs, denominators, scoring code, and failed runs were absent.

Conclusion: retain historical labels only as historical artifacts; current interpretation is internal structural agreement.

### JR-F-002 — The repository contained self-correction that had not propagated

The 2026-07-30 adversarial analysis had already downgraded claims about reproducibility, System Context, control points, evidence evolution, and method comparisons. The public and current summary layers did not fully inherit those downgrades.

Conclusion: establish machine-readable claim/evidence registries and enforce public claim synchronization.

### JR-F-003 — Configuration freezing was necessary but insufficient

The FCR froze declared configuration but could not reconstruct an experiment without prompts, models, raw outputs, evaluator outputs, failures, and scoring provenance.

Conclusion: preserve FCRs but require immutable run bundles under Validation Protocol v1.2.

### JR-F-004 — Evidence change had been conflated with reality change

The Evidence Isolation flow said "Reality changes -> New Evidence Package." Longitudinal historical cases normally hold reality fixed while the available evidence changes.

Conclusion: correct the constitutional flow to "Available evidence changes."

### JR-F-005 — Several principles were stronger than their proof

"Complex outcomes rarely have a single root cause" and "decision quality cannot exceed understanding quality" were presented as near-universal propositions.

Conclusion: restate them as bounded design heuristics. EDF should resist both forced single-cause and forced multi-cause narratives.

### JR-F-006 — Diagnostic Calibration risked false precision

Terms such as Consensus Index and Calibration Delta were not operationally validated.

Conclusion: retain them only as descriptive research ideas until metrics are defined and validated.

### JR-F-007 — The deployed web architecture was simpler than the repository

GitHub Pages deployed plain HTML/CSS while Next.js, vinext, Vite, Wrangler, Cloudflare worker code, and package dependencies remained in the tree.

Conclusion: remove the unused duplicate stack and make `static-site/` canonical.

## Theory Revision

The core grammar remains a viable working representation.

The stronger proposition, that EDF itself improves diagnostic performance over matched structured alternatives, remains unestablished.

The next proof must isolate EDF-specific semantic value from generic structure, model choice, evaluator affinity, prompt length, and case selection.


## External Methodology Cross-Check

An independent terminology review found that scientific authorities use reproducibility terms differently.

The National Academies (2019) uses computational reproducibility for recomputation with the same data/code/methods and replicability for new studies with new data. NIST metrology distinguishes repeatability under same conditions from reproducibility under changed conditions.

This challenged the audit's initial use of one unqualified EDF definition. The repository was revised to use execution reconstructability, within-condition repeatability, cross-executor reproducibility, and cross-case replication/generalization, with explicit held-constant/changed conditions.

Evidence record: EV-EDF-007.
